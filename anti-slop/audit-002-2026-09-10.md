## What changed

1. Em dashes removed from all user facing copy: `Hero.jsx`, and both partner
   entries in `content.js`. Replaced with periods, commas, or colons. A source
   scan for the character now returns zero across `src` and `index.html`.
   The hero body also no longer named stale areas ("employment", "inheritance");
   it now names corporate, property, private wealth, and family, which match the
   ten real practice areas.
2. The pinned opener no longer runs below 900px. `App.jsx` guards the hero
   timeline with `matchMedia('(min-width: 900px)')`, and the mobile stylesheet
   unpacks the stage: static hero, no card, practice layer visible. On mobile the
   hero pin spacer is gone (the hero now sits in normal flow).
3. Contact and footer links now carry a 44px minimum hit area
   (`.contact__list a`, `.footer__contact a`).
4. The two invented partner bios were deleted rather than rewritten, because no
   real wording exists to replace them. `summary` is gone from `PARTNERS`, the
   bio line is gone from the People detail, and the dead `.people__bio` rule was
   removed. An absent bio is honest; an invented one is not.
5. "Explore the practice" became "See the practice areas".
6. `.hero__stage > .practice` now uses `100svh` instead of `100vh`.
7. Arrows removed from the three "Book a consultation" CTAs and the hero ghost
   CTA. The two external links (WhatsApp, Instagram) lost the arrow and gained
   visually hidden "(opens in a new tab)" text, which is the accessible way to
   signal a new tab.
8. The consent row gained `min-height: 44px` and the checkbox grew to 1.35rem.
   The wrapping label already measured 152px tall, so the real target was never
   the box itself.
9. Em dashes in code comments normalised in `App.jsx` (8 lines) and
   `globals.css` (3 lines).
10. Mobile nav bug. Root cause: inside the mobile media query,
    `.site-header__mobile` was set to `display: grid` unconditionally, which beat
    the `hidden` attribute and kept the panel on screen at all times. It is now
    `display: none` with a `.site-header__mobile.is-open` rule to reveal it.

Two problems surfaced while fixing and were also corrected:

- Reduced motion showed all practice cards at 0.5 opacity, because the dim state
  is the base and only the active class restores it, which never runs without
  GSAP. The reduced motion block now sets card opacity to 1.
- A mobile regression introduced during this pass (the stage switched to
  `overflow: visible`, which let the ripple rings widen the page to 491px) was
  caught by re-running the overflow sweep and reverted to `overflow: hidden`.

## Reversal of finding 2 (same day, by request)

Finding 2 was fixed by disabling the pinned opener below 900px. The product owner
then asked for the morph, the card-to-gallery handoff, and the 01 to 10 scrub to
run on mobile too, so that fix was reverted by request.

Re-measured at 390x844:

- Pin active: hero 844px inside a 3376px pin spacer.
- y=700: stage 343px at 28px radius, letterhead card at opacity 1.00.
- y=1000: stage 347px at 26px radius, card 0.54, practice layer becoming visible.
- y=1400: stage 390px at 0px radius, practice 0.92.
- y=1800 to 2500: track travels -651px to -2275px, meter steps 03 to 10.
- No horizontal overflow (390/390), no console errors.

Also fixed in this pass: the attorneys layout. The base rules
`.people__media[data-media='a'] { grid-column: 1 }` and its siblings outranked the
mobile `.people__media { grid-column: auto }`, so on a phone the media and details
stayed in their desktop columns and paired with the wrong person. Both the mobile
and reduced motion blocks now override with attribute selectors, and the four
blocks stack in the order media A, detail A, media B, detail B at a single column
width. Verified: all four at left 20px, width 350px, tops 3533, 4010, 4216, 4693.

Desktop re-verified after the change: hero 900px inside a 3600px pin spacer, card
at opacity 1.00 at y=750, track to -2740px, meter to 10, no overflow, no errors.

The finding 2 tradeoff is therefore live again: the mobile opener is about four
screens of pinned scroll. That is a deliberate product choice, not an oversight.
