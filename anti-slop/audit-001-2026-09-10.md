# anti-slop audit 001

Date: 2026-09-10
Scope: hazicolaw landing page, mobile layout and copy
Mode: 2 (audit an existing project)

Evidence gathered by running the app in a real browser (Playwright, Chromium) at
390x844 and 360x800, scrolling the full document at each width, plus a source
scan of all user facing strings.

Baseline that passed:

- No document level horizontal overflow at either width: `scrollWidth` equals
  `clientWidth` at every scroll position sampled (390/390 and 360/360). R-03
  overflow: PASS.
- No console errors at either width or on the built output. R-35: PASS.

Priorities follow the rule tier: Hard Gate = HIGH, Purpose-Gate = MEDIUM,
Quality Locks and hygiene = LOW.

## HIGH

### 1. R-02: em dash in user facing copy (3 instances)

The character `—` appears in text a visitor reads. This is a Hard Gate.

- `src/components/Hero.jsx:29` hero body: "litigation — plainly, deliberately,"
- `src/data/content.js:82` partner summary: "Managing Partner — leads the firm and the matters it takes on."
- `src/data/content.js:94` partner summary: "Partner — works directly with clients across the practice areas."

Fix: replace each with a period, comma, colon, or parentheses.

### 2. R-03: the hero pin is a four screen slab on mobile

The desktop pinned sequence (hero folds to card, card opens, practice gallery
scrubs sideways) runs at full length on phones with no mobile variant.

Evidence:

- 390x844: hero element 844px, pin spacer 3376px.
- 360x800: hero element 800px, pin spacer 3200px.
- `.practice__track` reaches `left: -2330px` while pinned at 390.

Skill references: "Desktop-Only Layout", "100vh Sections". A phone user scrolls
roughly four screens through one pinned set piece before reaching normal content.

Fix options: skip the pin below the desktop breakpoint and render the hero and
practice gallery as plain stacked sections, or shorten the pin to one beat.

## MEDIUM

### 3. R-03: contact and footer links are under the 44px tap minimum

Measured link heights: 26px (`.contact__list` email and phone links), 23px
(`.footer__contact` email). Skill reference: "Under-Sized Targets".

Fix: give these links a 44px minimum hit area via padding or `min-height`,
without changing the visual line weight.

### 4. R-38 and R-23: partner summaries are invented placeholder bios

The `summary` lines in `PARTNERS` were written by the agent, not supplied, and
they present as real statements about each partner:

- "Managing Partner — leads the firm and the matters it takes on."
- "Partner — works directly with clients across the practice areas."

R-38 forbids fabricated content that looks real, and R-23 requires a clearly
labeled placeholder. Fix: replace with the partners' own wording, or mark as
placeholder until supplied.

### 5. R-15: generic CTA ("Explore")

The hero ghost button reads "Explore the practice". R-15 lists "Explore" among
the forbidden generic CTAs.

Fix: name the action, for example "See the ten practice areas" or "Read the
practice areas".

### 6. R-03: `height: 100vh` on the embedded practice layer

`.hero__stage > .practice` is sized with `height: 100vh`, which includes browser
chrome on mobile and can clip. Skill reference: "100vh Sections".

Fix: use `100svh` or `100dvh` to match the hero, which already uses `100svh`.

## LOW

### 7. R-08: arrows on most CTAs with no stated purpose

`↗` appears on "Book a consultation" (header, hero, mobile menu), "WhatsApp",
and "Instagram"; `↓` on the hero ghost button. R-08 is a Purpose-Gate rule, so
either write the purpose down or remove most of them.

### 8. R-03: consent checkbox is an 18px control

The consent input measures 18px wide. The wrapping `label` is the real hit
target and is large, so this is likely acceptable, but it should be confirmed
rather than assumed. Fix if confirmed: enlarge the control or its hit area.

### 9. R-02 hygiene: em dashes in code comments

`src/App.jsx` (8 lines), `src/styles/globals.css` (3 lines). Not user facing, but
the Delivery Gate asks for the character anywhere in the text. Cheap to normalize.

## Not findings

- Horizontal overflow: none at document level.
- Console errors: none.
- Fabricated statistics, testimonials, or trust claims: none found.
- Navbar links to nonexistent sections: none. Practice, People, and Contact all
  resolve.
- Color contrast: not measured in this pass; needs the contrast checker before
  it can be claimed either way.
